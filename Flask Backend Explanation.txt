🔹 1. What is Flask-SocketIO and why did you use it?
Answer: Flask-SocketIO is an extension that enables WebSocket communication in Flask apps. I used it to stream live stock data to the frontend in real time. It allows bi-directional communication between server and client, which is ideal for real-time apps like stock tickers or chat apps.

🔹 2. How do you handle concurrent data fetching for multiple stocks?
Answer: I use Python's threading.Thread to run a separate background thread for each subscribed stock symbol. Each thread fetches data every few seconds using jugaad_data.nse.stock_quote() and emits it to the frontend via SocketIO.

🔹 3. Is there any limitation to using threads like this in production?
Answer: Yes. Threads are managed by the Python interpreter and can become expensive if too many are created. CPython's GIL (Global Interpreter Lock) also limits true parallel execution of threads. For production-scale workloads, using async I/O or task queues like Celery is often more efficient.

🔹 4. How do you avoid race conditions or thread interference in your app?
Answer: Currently, there's no shared mutable state between threads except the active_subscriptions set, which is modified with care. For more safety, I could use threading locks (threading.Lock) or use thread-safe data structures like queue.Queue

Advantage	Description

✅ Asynchronous & Non-blocking	Uses asyncio, allowing many connections to be handled with fewer system resources.
✅ Scalable	More efficient under high load — can handle thousands of WebSocket clients with less CPU/memory.

❌ Problems with Flask + Socket.IO + Threading
Problem	Description

❌ Thread-based	Every stream uses a new thread → thread exhaustion is likely under high load.
❌ Blocking operations	Threads block the CPU even during network I/O.
❌ Complex scaling	Requires additional workers/queues (Celery, Redis) for heavy async workloads.
❌ Socket.IO ≠ WebSocket	Socket.IO adds overhead and isn't a pure WebSocket protocol (though it helps in some legacy cases).
❌ Not built for async	Flask is fundamentally WSGI (synchronous), so even with patches it’s less efficient for real-time apps.

## 🚀 What is **FastAPI**?

**FastAPI** is a **modern, high-performance web framework for building APIs with Python 3.7+** using:

- **Async & await** for non-blocking performance
- **Pydantic** for data validation
- **Starlette** under the hood for async power

It’s designed to be:
> ✨ Fast to build, fast to run, and fun to work with.

---

## 🔧 Core Features of FastAPI

| Feature              | Description |
|--------              |-------------|
| ⚡ **Blazing Fast** | Built on `Starlette` and `Pydantic`, it's faster than Flask and Django. |
| 🔄 **Asynchronous (async/await)** | Handles thousands of requests without blocking. |
| 🧪 **Automatic validation** | Uses Python type hints to auto-validate requests/responses. |
| 📄 **Auto-generated docs** | Swagger and ReDoc documentation is built automatically. |
| 💡 **Type-safe** | Built around Python type hints for better editor support, autocompletion, and fewer bugs. |
| 🔌 **WebSockets support** | Real-time support built-in (as you’re using now). |
| 🛡️ **Security tools included** | OAuth2, JWT, API Key auth, etc. all available and easy to use. |
